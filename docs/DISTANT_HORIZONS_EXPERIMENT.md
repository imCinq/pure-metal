# Distant Horizons path

This path is on by default when Distant Horizons 3.3.x is installed. It is tested on DH 3.3.4 only, and it has been visually validated in-game in one configuration (see the playtest observation below). It targets the official Distant Horizons 3.3.4 Fabric release for Minecraft 26.3. The preflight checks the mod version and selected compatibility-critical classes against the official 3.3.4 release, independently of the version string, JAR filename or ZIP packaging. Copies with the same checked classes can pass; modified builds that change those classes are rejected. This is not a guarantee for every modified build, since other classes and resources are not fingerprinted. Another 3.3.x version whose checked classes are identical to 3.3.4 also runs, with a log WARN and an "untested version" note on the F3 line. 3.3.3 matches these fingerprints; 3.3.2 does not. Other versions (3.2, 3.4, 4.x and so on), Iris, an OpenGL DH engine, or an unreadable configuration keep Pure Metal's existing backend fallback.

It turns on by itself when DH 3.3.x is installed with unchanged key classes, without Iris, and DH's renderer is `AUTO` or `BLAZE_3D`. When DH is installed and the switch is not set to false, the F3 line ends with `DH: on`, `DH: on (untested version)` (a 3.3.x other than 3.3.4) or `DH: off (<reason>)`, and the `DH: on` notes are left out when Pure Metal is not rendering. With the switch set to false, nothing is shown. The `DH: off` reason is given when the preflight fell back (Iris, version, modified build, engine setting, config unreadable, preflight error). The log has one plain WARN per cause, for example the DH version found against the 3.3.x required (tested on 3.3.4), or the engine DH is set to and the fix (set DH's rendering engine to AUTO and restart). There is no in-game chat message. Without DH, nothing is logged or shown. To turn the path off, start the client with `-Dpuremetal.experimentalDistantHorizons=false` and restart. The value is case-insensitive and ignores surrounding spaces, so `FALSE` and ` false ` also turn it off; any other value leaves it on. This does not change the DH config. While DH is installed and the path is off or fell back, Pure Metal refuses Metal and the game uses its normal graphics backend. The existing `puremetal.ignoreIncompatibleMods` override bypasses the normal safety guard and can force an incompatible DH setup onto Metal; do not use it to work around these checks.

DH 3.3.4 incorrectly reports Metal as OpenGL. The experiment follows the approach used by mcopt: only when Pure Metal is active, it gives DH the `VULKAN` API value so that DH's Blaze3D renderer avoids OpenGL-specific code. DH continues to send draw requests through the Metal backend. The label is a compatibility workaround, not a claim that the device is Vulkan. Other mods may interact with DH's reported API or change its configuration at runtime; those combinations have not been verified.

Builds and headless checks cannot establish that DH renders correctly; only in-game testing can. The single in-game observation below covers one configuration. Other dimensions, other upscaler and render-scale settings, errors over longer sessions and controlled GPU performance measurements have not been validated, so report any problems you see there.

Run `python3 tools/test_distant_horizons.py /path/to/DistantHorizons-3.3.4.jar [newer-3.3.x.jar ...]` with Java 25 for the headless engine-selection, release-class fingerprint and Fabric transformation checks. When a new DH release appears, run `python3 tools/compare_dh_jars.py /path/to/3.3.4.jar /path/to/new.jar` first: it reports which fingerprinted classes differ. A match alone does not establish runtime compatibility or satisfy the other preflight checks.

Playtest observation (2026-10-28): with Pure Metal's Metal backend active, DH rendered correctly in-game on an Apple M2 (Metal 3) with Sodium 0.9.3-beta.1, render scale 50% with MetalFX Temporal and a DH LOD distance of 256 chunks. The in-game FPS counter read about 155, a single reading and not a benchmark. Only this configuration was observed; the dimension and measurement duration were not recorded.

To remove this path, remove `DistantHorizonsExperiment.java`, `mixin/compat/DistantHorizonsApiMixin.java`, `tools/TestDistantHorizonsExperiment.java`, `tools/TestDistantHorizonsKnot.java`, `tools/test_distant_horizons.py` and this document, plus the one-line gate in `PureMetalBackend.java`, the gate in `PureMetalMixinPlugin.java`, and the mixin entry in `puremetal.mixins.json`.
